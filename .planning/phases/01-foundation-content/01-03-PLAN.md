    1. Create `.github/workflows/deploy.yml`:

       ```yaml
       name: Deploy to GitHub Pages

       on:
         push:
           branches: [main]
         workflow_dispatch:

       permissions:
         contents: read

       jobs:
         build-and-deploy:
           runs-on: ubuntu-latest
           steps:
             - name: Checkout
               uses: actions/checkout@v4

             - name: Setup Node
               uses: actions/setup-node@v4
               with:
                 node-version: 22
                 cache: npm

             - name: Install dependencies
               run: npm ci

             - name: Build
               run: npm run build

             - name: Deploy to External Repo
               uses: peaceiris/actions-gh-pages@v4
               with:
                 deploy_key: ${{ secrets.DEPLOY_KEY }}
                 external_repository: mkothari/finra-sie-exam-site
                 publish_branch: gh-pages
                 publish_dir: ./dist
       ```

       Key details:
       - Triggers on push to main AND manual workflow_dispatch
       - Uses `npm ci` (not `npm install`) for deterministic installs
       - Uses `peaceiris/actions-gh-pages@v4` with `deploy_key` secret for cross-repo push
       - `external_repository` is set to `mkothari/finra-sie-exam-site` (the public deploy repo)
       - `publish_dir: ./dist` matches Astro's default output directory
       - Node 22 with npm cache for faster CI

           </p>

           <div class="mb-8">

           </div>

           <div class="grid gap-4 sm:grid-cols-2">

                   <span class="text-sm text-gray-400">{Math.round(section.weight * 100)}% of exam</span>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions -> Public repo | Deploy key grants write access to the public deploy repo |
| CDN -> End user | Static files served from GitHub Pages CDN |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03a | Tampering | Deploy key | mitigate | SSH deploy key (not PAT) scoped to single repo; stored as GitHub secret; write access only to the public deploy repo |
| T-01-03b | Spoofing | GitHub Actions workflow | mitigate | Workflow triggers only on push to main and manual dispatch; no external triggers |
| T-01-03c | Denial of Service | Build failure blocks deploy | accept | Build failure is intentional -- broken schema should NOT deploy; manual workflow_dispatch allows retry |
</threat_model>
